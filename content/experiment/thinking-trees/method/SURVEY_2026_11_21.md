# Survey run: hierarchies of decision-making, 2026-11-21

Question: what do existing hierarchical decision systems teach us about designing a tree of LLM subagents as a way of processing/thinking?

Process: the main session acted as root (subagents here cannot spawn, see the first run). Layer 1 = six domain scouts in parallel. Root read their NEW LINKS, clustered them by how many branches raised them independently, and spawned layer 2 on the clusters. Root then scored relevance and convergence.

Every agent was explore-only and returned the report format from PROMPTS.md plus KEY IDEAS, NEW LINKS, DEAD ENDS and RELEVANCE (0-5). Source quality is stated per item: "URL" means the agent fetched or searched it, "memory" means it did not.

## Layer 1: six scouts

### agents-md (relevance 3/5, promising as mechanics, the spec itself is thin)
- nearest-wins scope: the instruction file closest to the edited file wins; an explicit user prompt beats all files. The only conflict rule the spec gives (agents.md).
- broad-always, narrow-on-demand: ancestor CLAUDE.md files load at launch, subdirectory ones only when the agent works there (code.claude.com/docs/en/memory).
- three-tier progressive disclosure: skill name+description always loaded, body on use, linked files on read. Each always-on listing costs context every turn (docs/en/skills).
- instructions are advice, not enforcement: CLAUDE.md is "context, not enforced configuration"; contradictory instructions make the model "pick one arbitrarily". Hard rules belong outside the prompt layer (memory page).
- fresh-context delegation: a subagent sees only its delegation message; only the final report returns; nesting capped at 3 (docs/en/sub-agents).
- size budget and staleness audit: keep files under about 200 lines; audit for stale or contradictory instructions.
- New links: `claudeMdExcludes` and large-codebases (stopping one branch's context leaking into another); auto memory as a child-to-future-parent feedback path; evidence on instruction-following under long or conflicting context.
- Dead ends: the AGENTS.md spec has no merge semantics, size guidance or inheritance. "88 files in the OpenAI repo" not verified.
- Open question: does nearest-wins, which suits static rules, hold when the narrow child has the least global context?

### octopus (relevance 3/5, promising but hypothesis-heavy)
- pick the program, not the muscles: brain selects a discrete behavior plus a few coarse parameters; the arm chooses execution (Sivitilli/Gire 2022, PMC9339708).
- compress on the way up: about 18M sucker sensory neurons converge onto about 140k brachial fibers; arm ganglia are proposed to filter (same review; hypothesis).
- novelty goes up, routine stays local: habituated input filtered, new input ascends (hypothesis).
- worker-to-worker side channel: the interbrachial commissure lets arms exchange state with no brain involved; cutting it impairs multi-arm locomotion.
- strongest signal wins, with a higher-level veto: local winner-take-all; the brain is one more competitor and can override (nature.com snippet, not fetched).
- the brain still learns from arm findings: in a maze task only the arm senses the path, yet the brain uses it (sciencedaily snippet).
- New links: arXiv 2402.01074 octopus-inspired robot control; commissure as the analogue of sibling subagents sharing a scratchpad; Zullo 2019 (central centers are not somatotopic and trigger multi-arm programs).
- Dead ends: "2/3 of neurons in the arms" is loosely sourced (review says about 350M arm vs about 170M brain; one popular article says 400k per arm). A severed arm is a reflex/pattern generator, not an agent with goals. Analogy breaks: arm circuits are fixed-purpose evolved hardware, LLM children are general reasoners; octopus layers run continuous loops with no one-shot report channel; arms do not report dead ends.
- Open question: when an arm's result contradicts the brain's goal, is anything beyond winner-take-all and central override used, and is the brain told about the suppressed alternative?

### kandev (relevance 3/5, promising but thin on hierarchy)
Identified: github.com/kdlbs/kandev, open-source AI kanban + dev environment, AGPL, Go backend, orchestrator sending tasks to agent CLIs (Claude Code, Codex, Copilot, Gemini via ACP). Look-alikes (kander, cline/kanban, kagan, openkanban) are unrelated.
- one task, one sandbox: each task gets its own git worktree; isolation is physical, not by prompt (README).
- parent hands down its session: sub-tasks resume from the parent's session. The opposite of our fresh-brief rule.
- agent files work for itself and peers: built-in MCP tools to create sub-tasks, message other tasks, read other conversations. Delegation is a durable record.
- stage pipeline with a different worker per stage: planner, implementer, reviewer columns, exportable as YAML.
- finish is a gate, not a worker's claim: in Office mode a successful run does not complete a task; review/approval need recorded approvals; rejection returns work to the Work stage (docs/public/office.md).
- persistent role identity apart from engine: a named role with instructions, permissions, history; model swappable underneath.
- durable state, lossy signals: event bus has no replay, so everything is recoverable from the DB (docs/ARCHITECTURE.md).
- humans own the final call: approvals inbox, budgets, global pause.
- Sibling (verified): Claude Code agent teams: teammates get a spawn prompt only, share a task list with dependencies and locked claiming, no nested teams. Documented failures: lead stops early, tasks unmarked, same-file edit conflicts.
- Dead ends: no documentation of how results flow up, or of conflict and dead-end handling.
- Open question: does inheriting the whole parent session destroy the context-size benefit of delegation?

### classic-layers (relevance 4/5, promising)
- stuck-triggers-child: a Soar impasse (no preferred option, or no way to proceed) automatically creates a substate whose only goal is to resolve it (Wikipedia Soar).
- only-results-return: when the substate finishes, its scratch work is deleted and only results go back.
- learn-the-answer: chunking compiles a resolved subgoal into a rule so the stuck point never needs a child again.
- lower-layer-veto / own sensing: in subsumption each layer runs alone and keeps its own sensor feedback; no central world model (Wikipedia Subsumption).
- plan-sequence-act split (3T, memory): slow deliberator, sequencer that handles failure locally, fast reactive layer; escalate only when the lowest capable layer cannot cope.
- commands-down-status-up (memory): goal with success criteria goes down; a short success/failure/blocked status with cause goes up. Options framework adds a termination condition per delegation. Feudal RL hides the parent's goal from the worker.
- New links: options termination conditions; blackboard / global workspace; predictive processing (send up only prediction error); HTN method-failure backtracking.
- Dead ends: Society of Mind (metaphor, no protocol); Global Workspace (about consciousness and broadcast); 3T page too thin to cite.
- Open question: should the root detect "stuck" or the child, given LLM children are poor at noticing?

### human-orgs (relevance 4/5, promising)
- purpose-plus-limits brief: delegate purpose, end state and constraints, not the method (army.mil mission command; Wikipedia Auftragstaktik).
- trust-and-understanding precondition: mission-type delegation fails on vague or misread intent (ADP 6-0).
- bypass alarm: VSM algedonic channel lets an urgent signal skip intermediate layers (Wikipedia VSM; sources disagree on where it lands).
- sporadic spot-audit: VSM System 3* samples an operation directly, bypassing normal reporting.
- same structure at every level: VSM is recursive; every child needs its own goal, rules and way to flag trouble.
- shared-trace coordination (stigmergy): coordination through traces in a shared medium, no messages (Wikipedia Stigmergy).
- Memory only: span of control about 3-7, Conway's law, principal-agent (reports flatter the reporter, drop uncertainty).
- New links: audit channel vs verifier children and how often; evidence-carrying reports; shared-artifact coordination (Heylighen).
- Dead ends: no failure taxonomy found for ADP 6-0; mapping VSM S1-S5 one-to-one onto a tree is a stretch; Conway and span of control not researched.
- Open question: which of these can an LLM parent act on, if it cannot judge a confident report without spending context re-checking?

### llm-trees (relevance 4/5, promising)
- brief-as-contract: vague delegations cause duplicated or misread work; fixed by objective, output format, tool guidance and boundaries (anthropic.com/engineering/multi-agent-research-system).
- pay-for-breadth: tokens explained about 80% of performance variance; multi-agent used about 15x chat tokens and beat single-agent by 90.2% on breadth-first research; 50 subagents for simple queries was a failure mode.
- coupled-work breaks: shared-context, many-dependency tasks (most coding) suit multi-agent poorly. Cognition argues parallel children hold conflicting implicit assumptions (cognition.com/blog/dont-build-multi-agents); working pattern is narrow-question subagents with no parallel writes.
- sequential penalty and checker (Kim et al., arXiv 2512.08296, abstract-level only): every multi-agent variant lost 39-70% on sequential reasoning; independent agents amplified errors 17.2x vs 4.4x with an orchestrator as validation bottleneck; gains vanish above about 45% single-agent baseline.
- pass-by-reference: children store bulky output externally and return a pointer.
- data-as-variable recursion: Recursive Language Models keep the input in a REPL variable and recurse on slices (arXiv 2512.24601, numbers from secondary summaries).
- New links: Tree of Thoughts / LATS (not fetched); compaction loss measurements; Kim et al. full paper.
- Dead ends: none fully; ToT/LATS fetch skipped for budget.
- Open question: what should the root's checker verify to get the 17.2x to 4.4x containment without re-running each child?
