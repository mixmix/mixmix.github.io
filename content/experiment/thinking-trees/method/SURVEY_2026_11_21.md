# Survey run: hierarchies of decision-making, 2026-11-21

Question: what do existing hierarchical decision systems teach us about designing a tree of LLM subagents as a way of processing/thinking?

Process: the main session acted as root (subagents here cannot spawn, see the first run). Layer 1 = six domain scouts in parallel. Root read their NEW LINKS, clustered them by how many branches raised them independently, and spawned layer 2 on the clusters. Root then scored relevance and convergence.

Every agent was explore-only and returned the report format from PROMPTS.md plus KEY IDEAS, NEW LINKS, DEAD ENDS and RELEVANCE (0-5). Source quality is stated per item: "URL" means the agent fetched or searched it, "memory" means it did not.

## Layer 1: six scouts

### agents-md (relevance 3/5, promising as mechanics, the spec itself is thin)
- nearest-wins scope: the instruction file closest to the edited file wins; an explicit user prompt beats all files. The only conflict rule the spec gives (agents.md).
- broad-always, narrow-on-demand: ancestor CLAUDE.md files load at launch, subdirectory ones only when the agent works there (code.claude.com/docs/en/memory).
- three-tier progressive disclosure: skill name+description always loaded, body on use, linked files on read. Each always-on listing costs context every turn (docs/en/skills).
- instructions are advice, not enforcement: CLAUDE.md is "context, not enforced configuration"; contradictory instructions make the model "pick one arbitrarily". Hard rules belong outside the prompt layer (memory page).
- fresh-context delegation: a subagent sees only its delegation message; only the final report returns; nesting capped at 3 (docs/en/sub-agents).
- size budget and staleness audit: keep files under about 200 lines; audit for stale or contradictory instructions.
- New links: `claudeMdExcludes` and large-codebases (stopping one branch's context leaking into another); auto memory as a child-to-future-parent feedback path; evidence on instruction-following under long or conflicting context.
- Dead ends: the AGENTS.md spec has no merge semantics, size guidance or inheritance. "88 files in the OpenAI repo" not verified.
- Open question: does nearest-wins, which suits static rules, hold when the narrow child has the least global context?

### octopus (relevance 3/5, promising but hypothesis-heavy)
- pick the program, not the muscles: brain selects a discrete behavior plus a few coarse parameters; the arm chooses execution (Sivitilli/Gire 2022, PMC9339708).
- compress on the way up: about 18M sucker sensory neurons converge onto about 140k brachial fibers; arm ganglia are proposed to filter (same review; hypothesis).
- novelty goes up, routine stays local: habituated input filtered, new input ascends (hypothesis).
- worker-to-worker side channel: the interbrachial commissure lets arms exchange state with no brain involved; cutting it impairs multi-arm locomotion.
- strongest signal wins, with a higher-level veto: local winner-take-all; the brain is one more competitor and can override (nature.com snippet, not fetched).
- the brain still learns from arm findings: in a maze task only the arm senses the path, yet the brain uses it (sciencedaily snippet).
- New links: arXiv 2402.01074 octopus-inspired robot control; commissure as the analogue of sibling subagents sharing a scratchpad; Zullo 2019 (central centers are not somatotopic and trigger multi-arm programs).
- Dead ends: "2/3 of neurons in the arms" is loosely sourced (review says about 350M arm vs about 170M brain; one popular article says 400k per arm). A severed arm is a reflex/pattern generator, not an agent with goals. Analogy breaks: arm circuits are fixed-purpose evolved hardware, LLM children are general reasoners; octopus layers run continuous loops with no one-shot report channel; arms do not report dead ends.
- Open question: when an arm's result contradicts the brain's goal, is anything beyond winner-take-all and central override used, and is the brain told about the suppressed alternative?

### kandev (relevance 3/5, promising but thin on hierarchy)
Identified: github.com/kdlbs/kandev, open-source AI kanban + dev environment, AGPL, Go backend, orchestrator sending tasks to agent CLIs (Claude Code, Codex, Copilot, Gemini via ACP). Look-alikes (kander, cline/kanban, kagan, openkanban) are unrelated.
- one task, one sandbox: each task gets its own git worktree; isolation is physical, not by prompt (README).
- parent hands down its session: sub-tasks resume from the parent's session. The opposite of our fresh-brief rule.
- agent files work for itself and peers: built-in MCP tools to create sub-tasks, message other tasks, read other conversations. Delegation is a durable record.
- stage pipeline with a different worker per stage: planner, implementer, reviewer columns, exportable as YAML.
- finish is a gate, not a worker's claim: in Office mode a successful run does not complete a task; review/approval need recorded approvals; rejection returns work to the Work stage (docs/public/office.md).
- persistent role identity apart from engine: a named role with instructions, permissions, history; model swappable underneath.
- durable state, lossy signals: event bus has no replay, so everything is recoverable from the DB (docs/ARCHITECTURE.md).
- humans own the final call: approvals inbox, budgets, global pause.
- Sibling (verified): Claude Code agent teams: teammates get a spawn prompt only, share a task list with dependencies and locked claiming, no nested teams. Documented failures: lead stops early, tasks unmarked, same-file edit conflicts.
- Dead ends: no documentation of how results flow up, or of conflict and dead-end handling.
- Open question: does inheriting the whole parent session destroy the context-size benefit of delegation?

### classic-layers (relevance 4/5, promising)
- stuck-triggers-child: a Soar impasse (no preferred option, or no way to proceed) automatically creates a substate whose only goal is to resolve it (Wikipedia Soar).
- only-results-return: when the substate finishes, its scratch work is deleted and only results go back.
- learn-the-answer: chunking compiles a resolved subgoal into a rule so the stuck point never needs a child again.
- lower-layer-veto / own sensing: in subsumption each layer runs alone and keeps its own sensor feedback; no central world model (Wikipedia Subsumption).
- plan-sequence-act split (3T, memory): slow deliberator, sequencer that handles failure locally, fast reactive layer; escalate only when the lowest capable layer cannot cope.
- commands-down-status-up (memory): goal with success criteria goes down; a short success/failure/blocked status with cause goes up. Options framework adds a termination condition per delegation. Feudal RL hides the parent's goal from the worker.
- New links: options termination conditions; blackboard / global workspace; predictive processing (send up only prediction error); HTN method-failure backtracking.
- Dead ends: Society of Mind (metaphor, no protocol); Global Workspace (about consciousness and broadcast); 3T page too thin to cite.
- Open question: should the root detect "stuck" or the child, given LLM children are poor at noticing?

### human-orgs (relevance 4/5, promising)
- purpose-plus-limits brief: delegate purpose, end state and constraints, not the method (army.mil mission command; Wikipedia Auftragstaktik).
- trust-and-understanding precondition: mission-type delegation fails on vague or misread intent (ADP 6-0).
- bypass alarm: VSM algedonic channel lets an urgent signal skip intermediate layers (Wikipedia VSM; sources disagree on where it lands).
- sporadic spot-audit: VSM System 3* samples an operation directly, bypassing normal reporting.
- same structure at every level: VSM is recursive; every child needs its own goal, rules and way to flag trouble.
- shared-trace coordination (stigmergy): coordination through traces in a shared medium, no messages (Wikipedia Stigmergy).
- Memory only: span of control about 3-7, Conway's law, principal-agent (reports flatter the reporter, drop uncertainty).
- New links: audit channel vs verifier children and how often; evidence-carrying reports; shared-artifact coordination (Heylighen).
- Dead ends: no failure taxonomy found for ADP 6-0; mapping VSM S1-S5 one-to-one onto a tree is a stretch; Conway and span of control not researched.
- Open question: which of these can an LLM parent act on, if it cannot judge a confident report without spending context re-checking?

### llm-trees (relevance 4/5, promising)
- brief-as-contract: vague delegations cause duplicated or misread work; fixed by objective, output format, tool guidance and boundaries (anthropic.com/engineering/multi-agent-research-system).
- pay-for-breadth: tokens explained about 80% of performance variance; multi-agent used about 15x chat tokens and beat single-agent by 90.2% on breadth-first research; 50 subagents for simple queries was a failure mode.
- coupled-work breaks: shared-context, many-dependency tasks (most coding) suit multi-agent poorly. Cognition argues parallel children hold conflicting implicit assumptions (cognition.com/blog/dont-build-multi-agents); working pattern is narrow-question subagents with no parallel writes.
- sequential penalty and checker (Kim et al., arXiv 2512.08296, abstract-level only): every multi-agent variant lost 39-70% on sequential reasoning; independent agents amplified errors 17.2x vs 4.4x with an orchestrator as validation bottleneck; gains vanish above about 45% single-agent baseline.
- pass-by-reference: children store bulky output externally and return a pointer.
- data-as-variable recursion: Recursive Language Models keep the input in a REPL variable and recurse on slices (arXiv 2512.24601, numbers from secondary summaries).
- New links: Tree of Thoughts / LATS (not fetched); compaction loss measurements; Kim et al. full paper.
- Dead ends: none fully; ToT/LATS fetch skipped for budget.
- Open question: what should the root's checker verify to get the 17.2x to 4.4x containment without re-running each child?

## Layer 2: seven follow-ups

Each took the claims from layer 1 that several branches pointed at, and had to mark every claim SUPPORTED / PARTLY / CONTRADICTED / UNVERIFIED.

Source caveat for everything below: layer-2 agents cite many 2025-26 preprints, mostly seen only as abstracts or search snippets. The root has not independently opened any of them. Treat the specific numbers as leads to spot-check, not facts.

### verify: cheap verification of child reports (relevance 4/5)
- C1 PARTLY. Kim et al. numbers match (17.2x vs 4.4x, 39-70%, 45%) but the 39-70% loss is on planning tasks only, and the paper says the error-amplification effect is not significant once other metrics are controlled. The "orchestrator as validation bottleneck" claim from layer 1 is weakened. (arxiv.org/html/2512.08296)
- C4 PARTLY. LLM judges reading a closing "success" message scored AUROC at most 0.65 at spotting false success; a cheap TF-IDF classifier on trajectory text reached about 0.83-0.94 (arXiv 2606.09863, snippet/digest). So judging prose is near chance, but "re-check with your own context" is too strong: cheap non-LLM signals work.
- check the world, not the words: compare the claim to environment state or artifacts.
- verifier from a different model family: self-verification gains little; cross-family does better (arXiv 2512.02304).
- verification is not reliably cheaper than generation: the gap shrinks as the generator gets stronger (arXiv 2412.02674, 2510.13744).
- verbalized confidence is a weak gate; consistency across sampled answers beats self-report (arXiv 2509.25532).
- Dead end: nothing tests "what I did NOT check" or evidence-quote fields; children may fabricate plausible evidence.
- Open: do evidence pointers and NOT CHECKED fields reduce false success, or just get faked?

### lateral: lateral channels vs a strict tree (relevance 4/5)
- stigmergy definition SUPPORTED (Wikipedia). Octopus commissure PARTLY: confirmed to exist, but the review only says severing it "affects the arm's ability to coordinate", weaker than layer 1's "impairs multi-arm locomotion". Agent-teams doc facts SUPPORTED (shared task list, file-lock claiming, mailbox, no nested teams). Cognition quote SUPPORTED.
- lateral only for independent work: the agent-teams doc says teams are poor for sequential tasks, same-file edits or many dependencies; cost scales per teammate; 3-5 teammates advised.
- debate against anchoring: peers try to disprove each other's theories; the doc recommends it for open-ended diagnosis.
- conformity risk: LLM agents show measurable conformity (BENCHFORM, snippet), so reading peers' conclusions early plausibly anchors.
- Minimal mechanism proposed: an append-only dead-ends ledger, one line per entry {approach tried, why it failed, evidence pointer}. Negative results only, never conclusions, so it cannot anchor. Children read before starting and append on failure; entries capped; root can prune.
- Would break it: a wrong or over-general entry prunes a valid path; ledger bloat; stale reads from concurrent siblings; a "dead end" that depends on context the ledger omits; ledger text treated as instructions.
- Dead end: no head-to-head test of ledger vs message-passing. kandev claim not rechecked.

### stuck: detecting stuck and handling dead ends (relevance 4/5)
- external repetition monitor: OpenHands runs a detector outside the agent over the event history (same action/observation 4+ times, same action with an error 3+ times, agent-only monologue 3+ messages, A/B ping-pong 6+ cycles), on by default (docs.openhands.dev; thresholds ambiguous across sources).
- hard budgets as backstop: step, cost, timeout and consecutive-failure limits; SWE-agent reportedly autosubmits the partial patch, i.e. a "stuck" return that still carries partial work (secondary blogs only).
- self-judgment unreliable without outside signal: self-correction without external feedback is weak (arXiv 2310.01798). No direct measure of "knows it's stuck" found. So the stuck signal should come from outside observation, not the child's feeling. This answers layer-1's open question (who detects stuck).
- failure taxonomy: MAST lists step repetition among 14 multi-agent failure modes (arXiv 2503.13657).
- experience-driven early stop (chunking analogue): EET stores abstracted past resolutions, cost down 19-55%, but stores successes only. Negative-experience memory is a gap.
- Soar chunking (C1), options termination (C2), VSM alarm (C4) and octopus habituation (C5) were UNVERIFIED in this pass.
- Open: for non-code thinking tasks with no actions to repeat, what replaces the repetition monitor?

### report: what a report should carry (relevance 4/5)
- C3 SUPPORTED (Anthropic: store externally, pass a reference). C5 SUPPORTED (AACL 2026 "epistemic erosion", snippet). C1 UNVERIFIED: no LLM evidence for "report only the delta from the parent's expectation". C2 UNVERIFIED. C4 PARTLY (RLM beats a compaction baseline by a median of 26%, abstract only).
- omission beats invention: summaries mostly drop things (about 66% of distortions in one study), and LLM judges are worse at spotting what is missing than what is extra. So the parent cannot easily audit what it is sent.
- hedge loss: qualifiers and uncertainty get dropped; causal language gets amplified.
- unstated decisions: Cognition says actions carry implicit decisions, so a report should name the assumptions the child made.
- format tax: strict JSON-style formats can hurt reasoning; free reasoning first, then fill fields, reduces the harm. Effect varies by task.
- Proposed 12-field template (S = speculative): BRANCH; VERDICT; CONFIDENCE + the one fact; EXPECTED-VS-FOUND (S); FINDINGS tagged verified-with-URL or memory; ASSUMPTIONS MADE; DISCONFIRMING / SURPRISES (S); NOT CHECKED; RULED OUT; POINTERS (spill bulky output to a file above about 500 words, S threshold); BLAST RADIUS / CHANGES MADE; OPEN QUESTION / NEXT STEP.
- Dead end: no study of structured vs free summaries on hedge retention.
- Open: does a mandatory NOT CHECKED field raise omission recovery, or fill with boilerplate?

### search: search over reasoning branches (relevance 4/5)
- C1 SUPPORTED: Tree of Thoughts 74% vs CoT 4% on Game of 24 (arXiv 2305.10601); call counts not on the page. C2 SUPPORTED: LATS 92.7% pass@1 HumanEval, but credits "environment for external feedback" (arXiv 2310.04406). C3 PARTLY: search hits say matched-compute self-consistency often beats proposed strategies (EMNLP 2024) and PRM-guided tree search fails to beat best-of-N (arXiv 2502.11183); neither read in full. C4 PARTLY: LLMs struggle to self-correct without external feedback (arXiv 2310.01798).
- difficulty-gated compute: search gains vary with prompt difficulty; adaptive allocation beat best-of-N by over 4x in efficiency (Snell et al., arXiv 2408.03314).
- external-feedback pruning: tree search pays off when the branch score is grounded (tests, environment, tool results); ungrounded self-scores are the weak point.
- branch only when needed: Chain-in-Tree cuts tokens and calls 75-85% on GSM8K/Math500 with often negligible loss (arXiv 2509.25835).
- cheap baseline first: sample N independent children and take the majority or verified answer before building a tree.
- dead-branch signals (the agent's own synthesis, not checked): failed verifier or test, grounded partial result contradicting constraints, budget exhaustion, disagreement with siblings.
- subagent-as-branch vs step-as-branch (the agent's own reasoning): a node costs a whole tool-using run; context isolation keeps root context small; no shared state so duplicated work is likely.
- Dead end: nothing quantified for subagent-level branches.
- Open: for open-ended tasks with no cheap verifier, is there a pruning signal better than sibling disagreement?

### inherit: fresh brief vs inherited context (relevance 5/5)
- Claude Code docs define a "fork" subagent that inherits the entire conversation and reuses the parent's prompt cache, on by default since v2.1.302 (code.claude.com/docs/en/sub-agents, "How forks differ from other subagents"). Non-fork subagents start fresh. C1/C2/C5 SUPPORTED; C4 PARTLY.
- cache makes the prefix cheap: cache read is 0.1x base input (0.05x for Sonnet 5.5 and Opus 5.5), 5-minute write 1.25x, 1-hour write 2x; prefixes must be byte-identical.
- cheap is not clean: caching cuts price and latency but not context rot. A cached 100k prefix is still 100k tokens in the window. Chroma context-rot work tested 18 models; focused ~300-token prompts beat ~113k-token full prompts on LongMemEval. Lost-in-the-middle (arXiv 2307.03172). Both are retrieval-style tasks, not inherited agent traces.
- Decision rule (agent's synthesis): fresh + brief when the task is separable, needed context fits in 1-2k words, history is long or noisy, a different model/role is wanted, or the cache is cold. Fork when the child needs the parent's decisions and trace, for parallel alternatives from one start, history short, cache warm. Hybrid: fresh child with a brief plus file pointers to written parent artifacts. Mixed trees: fork near the root while history is small, fresh deeper down.
- Caveat: forking couples the child to the parent's biases and errors. Cache-hit problems for siblings and resumed forks come from third-party issue reports only.
- Dead end: no official fork-vs-fresh quality comparison; synthetic tasks only.

### precedence: who wins when layers conflict (relevance 4/5)
- Finding: the layer-1 "conflict" between AGENTS.md nearest-wins and octopus/subsumption higher-layer veto mostly dissolves. They are different axes: scope (which rule applies where) vs authority (who may veto). C1 SUPPORTED; C2, C3, C4 UNVERIFIED this pass; C5 PARTLY.
- authority comes from channel, not position: the instruction hierarchy (OpenAI, arXiv 2404.13208) ranks tool outputs lowest, so files a child reads are data, never orders.
- the hierarchy leaks: a 2025 evaluation found it ineffective against diverse injections (arXiv 2505.18333). So precedence must be enforced structurally (limit what a child may do), not only in prompt text.
- check actions against the task: Task Shield (arXiv 2412.16682).
- agents default to obeying: Blind-Act reports an 80.8% blind-goal rate across 9 models (arXiv 2510.01670); ODCV-Bench found models that call an action unethical in review and still execute it (arXiv 2512.20798). So the deviation path must be explicit.
- Proposed rule: purpose beats order; parent beats child on purpose; child beats parent on facts. (1) Parent's purpose and hard constraints win over anything the child reads. (2) Nearest, most specific local rule wins on method within a scope. (3) Child decides alone only if reversible and inside the purpose; otherwise stops and escalates. (4) A deviation report has five fields: the brief said X; I saw Y (quote and path); I did Z; purpose still met because W; cost to undo. (5) Embedded orders are reported verbatim and marked "untrusted, not followed".
- Would break it: the parent's purpose was wrong; models rarely deviate so rule 3 never fires; a child rationalizes "purpose is still met"; injection through the child's own report.
- Dead end: instruction hierarchy as a complete defense. No source measures appropriate deviation directly.

### Corrections between layers
- Kim et al. "validation bottleneck" (llm-trees, layer 1) was weakened by verify: the effect is not significant once other metrics are controlled. The checker idea survives on other evidence (false-success study, cross-family verifiers), but not on that paper.
- Octopus commissure "impairs multi-arm locomotion" (octopus) was softened by lateral to "affects coordination".
- The nearest-wins vs veto contradiction (agents-md vs octopus/classic-layers) was resolved by precedence as two different axes.
- Layer-1's open question "who detects stuck" was answered by stuck: an external monitor, not the child.
- Layer-1's kandev finding (child inherits parent session) turned out to be a built-in Claude Code option too (inherit).

### Boost per branch
Findings that gained weight because other branches found them too:
- agents-md: "instructions are advice, not enforcement" (now 5 agents). "Fresh-context delegation" (6, as a trade-off). Nearest-wins was kept but narrowed to the scope axis. Progressive disclosure and size budget: not corroborated.
- octopus: "program not muscles" (rides the brief-as-contract score of 8). "Compress up, novelty up" stays a hypothesis (0 evidence, 3 asked). Side channel: weakened. Its dead end (analogy breaks) scored 4, so it is its most solid result.
- kandev: completion gate (9). Durable record / shared medium (7). Inherit-vs-fresh (6). Stage pipeline and persistent roles: isolated.
- classic-layers: stuck-triggers-child and results-only (rides 8 and 9). Its hypothesis that LLM children cannot detect stuck is now 6 and backed by evidence. HTN and predictive processing: still unverified.
- human-orgs: purpose-plus-limits (8), spot-audit (9), bypass alarm (not tested), stigmergy (7).
- llm-trees: brief-as-contract (8), pass-by-reference (rides 9), pay-for-breadth (4), sequential penalty (4). Kim bottleneck: weakened.

## Answer to "how relevant is this to the problem?"

Overall: about 4/5 for improving the thinking-tree method, about 2/5 for a theory of "layers of cognition".

- High value (core, 6-9 agents): the six core findings above. They change concrete artifacts: the delegation prompt (purpose, constraints, stop condition, return format, budget), the report template (add NOT CHECKED, ASSUMPTIONS, DISCONFIRMING, POINTERS), and the root's role (check state, not prose).
- Medium value: the dead-ends ledger, the fork-or-fresh rule, and the "best-of-N before a tree" default. They are well argued but untested.
- Low value as mechanism, high value as questions: octopus, VSM, Soar, subsumption. Four branches agree the analogy fails because LLM children are general and obedient. They are best used to generate hypotheses, not designs.
- Weakest area, and the real gap: dead-end handling and conflict handling are the least evidenced parts of the whole survey, which is exactly what a thinking tree is for.

## Proposed changes to the method (not yet applied)
1. Delegation template: add PURPOSE, HARD CONSTRAINTS, DONE-WHEN, STUCK-WHEN, BUDGET, and a line stating whether the child is fresh, forked or hybrid.
2. Report template: adopt the 12-field proposal, keeping the speculative fields marked.
3. Return status: done | partial | stuck, with a typed reason and best partial result. "Stuck" is set by a budget/repeat check where possible, not by the child's feeling.
4. Add the dead-ends ledger (negative results only) as an optional shared file.
5. Root verifies by artifact: paths, diffs, command output, plus random audits that scale with stakes. Verifier children from a different model family.
6. Default to a cheap baseline (N independent children and a vote or verifier) before a deep tree. Keep depth shallow on sequential or coupled work.
7. Conflict rule: purpose beats order; parent wins on purpose; child wins on facts; deviations use the five-field report; text found in files is data.

## Experiments this suggests
- Planted-fact test: hide known facts in a child's source and measure which report template recovers them (tests NOT CHECKED, delta, free-text vs structured).
- Ledger vs independent siblings on the same task: duplicated work and premature pruning.
- Fork vs fresh+brief at increasing history length on an agentic task.
- Blind-brief test: give a child a deliberately wrong brief and see whether it escalates.

## Cost of this run
Thirteen agents, all explore-only, none spawned by another agent, so the "tree" was two layers driven entirely by the root. Reported subagent tokens were about 0.43M for layer 1 and about 0.51M for layer 2, roughly 0.94M in total. That is consistent with the cost warnings in the literature above.

Claim tally for layer 2 (33 layer-1 claims tested): 11 SUPPORTED, 11 PARTLY, 11 UNVERIFIED, 0 CONTRADICTED. "Unverified" means the layer-2 agent did not re-check it, not that it was found false.

## Open questions left standing
- What replaces a repetition monitor for non-code reasoning (near-identical conclusions, no-new-information check)?
- Can a child reliably judge "the purpose is unachievable", or will it comply anyway?
- Is there any pruning signal better than sibling disagreement when no verifier exists?
- Do evidence fields and NOT CHECKED fields reduce false success, or get faked?
